# 用量与计费规格

## 目标

为每次 Agent 运行建立可重放安全的用量账本，并在此基础上提供套餐、订阅、余额、兑换码和配额能力。计费只做本地账本，不接入真实支付网关。

## 核心流程

1. Runner 产生 `usage` 流事件；服务端以 `eventId` 作为逻辑运行唯一键。
2. 首次入账同时写入事件明细、模型明细、每日汇总、月度汇总和余额扣款；重复 `eventId` 返回原结果且不重复扣款。
3. 非管理员用户在计费开启时，执行前检查有效套餐、余额和日/周/月 Token 或费用配额；配额可以分别覆盖用户、Agent 和 Workspace。
4. 管理员通过套餐、订阅、余额调整和兑换码管理用户账务；兑换码使用以用户和兑换码组合幂等。
5. 普通用户只能查看自己的用量与账务；管理员可以筛选用户并查看管理接口。

## 可验证行为

- Token 按输入、输出、缓存读取、缓存写入、推理五类统计。
- 用量支持 Agent、Workspace、模型、日期范围筛选，日期范围最多 365 天。
- CSV 导出限制 10,000 条，单元格防止公式注入。
- 兑换码支持余额、套餐和试用三种类型；过期、次数耗尽、重复使用均拒绝。
- 余额调整和兑换码消费使用幂等键/唯一约束，失败不产生半笔账务。
- 配额超限返回明确窗口和重置时间；管理员绕过配额，计费关闭时不拦截。
- 运行时按当前 Session 的用户、Agent、Workspace 作用域依次检查配额；任一作用域超限都会阻断执行。

## 非目标

- 不接入支付网关、发票、税费或自动扣款。
- 不复制参考仓库中依赖外部 Kaboo 服务的运营后台；只保留本地可验证的价格估算和账务接口。
